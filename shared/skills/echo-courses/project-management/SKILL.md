# Project management

## 1. Start: define done
One-paragraph charter: goal (measurable — "100 flat bookings by March"), scope (what's in and out), deadline, budget, sponsor/decision maker, success measures.

## 2. Break it down
Work breakdown: phases → deliverables → tasks small enough for 1–3 days. Each task has an owner and an estimate. Mark dependencies (B can't start before A).

## 3. Schedule and budget
Put tasks on a timeline (Gantt in a sheet or a tool), find the critical path (the chain that sets the end date), add 15–20% buffer. Budget = people × time + materials + contingency (10%).

## 4. Risks
List what could go wrong, how likely and how bad, and the plan (avoid, reduce, accept, share). Review weekly. Top Indian construction/real-estate risks: approvals, monsoon delays, contractor cash flow, price changes.

## 5. Running it
- **Kanban board**: To do / Doing / Done, limit work in progress.
- **Agile sprints** (software): 1–2 week sprints, planning, daily 15-minute stand-up (done, doing, blocked), review, retrospective.
- Weekly status: green/amber/red, what's done, what's next, risks, decisions needed. Escalate early.
- Change control: new requests are written down with impact on time and cost before saying yes.

## 6. Closing
Confirm deliverables with the sponsor, hand over documents, celebrate, and run a lessons-learned session: what to keep, what to change.

## 7. Echo can help
Turn the task list into Echo tasks with due dates, set reminders for milestones, and use the meeting-action-items skill after meetings.
